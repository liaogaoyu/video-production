# 人民币账户与实际消耗结算

系统采用人民币余额。API及SQLite所有金额均为整数“分”，前端显示元（两位小数）。不再配置平台积分面值。原版本默认100积分/元对应1分/积分，因此该默认面值的已有余额、流水可原数值迁移；非默认面值且存在流水时升级拒绝启动，必须先显式迁移，不能静默改账。历史免费任务没有收费记录，不追溯扣款。

## 管理后台配置

- SMTP：地址、465/587端口、账号、发信邮箱、授权码；保存并验证真实投递后再开放注册。SMTP凭据加密保存。公开注册前应部署HTTPS。
- 微信：微信号、二维码、充值说明。管理员按实收人民币充值，赠送金额也用元填写。充值有幂等标识、操作人、必填备注；调整余额通过追加流水完成。
- 国内渠道：默认采购成本260元/6200官方积分；国际渠道：30元/1500官方积分。两个渠道分别配置成本加价比例。模型不需要各自配置销售价格。
- 每个视频渠道可配置每秒预估官方积分，仅用于生成前预扣，实际金额不按这个估计结算。旧模型估计表保留兼容读取，但渠道估计优先；没有任何估计规则的视频暂不允许提交。
- 生图成本默认0.10元/张，独立配置加价，按真实成功保存的交付张数结算。
- 注册及付费生成默认关闭，管理员在关闭期间仍可使用原内部生成入口。启用付费前确认账号池、模型连接与预估参数均有效。

最终视频费用（分）= ceil(官方实际积分 × 渠道采购金额（分） / 购得官方积分 × (1 + 成本加价比例))。生图按实际交付张数乘成本和加价，再向上取整到分。加价50%是成本加价，销售毛利率约33.33%。汇率与加价按提交报价快照保存，不随以后调价改变。

## 预扣、多退少补

1. 报价有效5分钟，冻结内容与费率快照；素材变化需重新报价。界面明确提示这是预计预扣、最终可能补款。
2. 确认报价时，在同一SQLite事务中创建任务、减少可用余额并记录“预扣待结算”。重复确认返回原任务，不重复预扣。
3. 视频成功保存可交付结果后，取得匹配任务号的官方实际消耗才结算。实际费用较少自动退差额，较多自动补扣。
4. 可用余额不足以补齐时，扣除可用部分、记录待补金额，余额保持非负。充值后按旧账顺序自动补齐；待补款清零前禁止创建新的付费任务，已有任务继续查询和下载。
5. 生成失败、授权失效或取消未开始任务全额退款。提交状态未知、下载恢复中、实际消耗未出现或查询异常时保留预扣并标记待结算，不使用预测值或账号余额差冒充实际费用。
6. worker后台定期核账（每条异常账单约60秒后重试），独立于生成调度。查询只读，不重新生成。到账、预扣、结算、退款及补款均有账本流水和幂等业务键。
7. 管理员核实无法交付可终止并退款。已成功交付但缺实际消耗的任务不能使用“无法交付退款”入口掩盖账务问题，应恢复官方登录/查询并继续核账。

## 官方实际消耗证据

- 国内CLI 1.4.21：成功query_result的顶层credit_count，submit_id必须严格匹配当前任务。历史任务列表commerce_info.credit_count可交叉核对。只读查询已验证Fast任务54、54、84积分；不将Fast消耗推导给其他模型。
- 国际网页：/commerce/v1/benefits/user_credit_history，筛选与任务submit_id一致、history_type=2且status=Checked的生成扣费记录，以history_id去重并保留receiptId。分页完整遍历、有冲正、数值冲突或多条不同扣费凭据时暂停自动核账。详情extra.credits_consume已与实际流水交叉验证。forecast_generate_cost是预测，不用来结算。
- 数值0有效；字段缺失、任务号不符、格式错误不是0。所有结算保留来源、官方任务号、账单记录号和核对时间。网页内部接口可能变化，异常时停止结算并继续查询。

真实既有国际任务的隔离结算已验证：标准版预扣2元、实际68积分折合1.36元，退0.64元；Fast预扣0.50元、实际40积分折合0.80元，补0.30元。测试未新生成视频、未影响正式用户余额。

## 权限与公共资产风格

用户只能访问自己的项目、媒体、任务、导出、事件和账单；账号池、接口密钥、代理及渠道成本由管理员管理。公共资产风格提示词与公共参考图在新生图任务中组合并保存快照，原资产文本和历史任务不受修改影响，场景无人规则保留。

## Linux升级

备份原代码、master key、媒体，并用SQLite backup API备份数据库。先在私有副本迁移两次、验证integrity_check和原始业务数量，运行测试；不要在副本启动自动生成worker。

发布tracked源文件及webapp/dist，保留旧哈希文件与既有运行时数据。使用npm install --omit=dev，重启API/worker；核对代理、登录、账号池和新后台入口。发布默认不自动开启注册或收费。

若升级后已产生充值或账单，不得直接恢复旧数据库丢弃新账，应先备份当前库再前向修复/对账。
