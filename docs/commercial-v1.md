# 商业化 V1：部署与开通

本版本在原有 Node/React Storydock 上增加邮箱身份、私有工作区、积分钱包、统一模型目录和项目公共资产风格。无需另建前端服务，Linux API/worker 仍使用现有 systemd 与 SQLite。

## 上线默认值

- 公开注册、商业扣费默认关闭。现有账号迁移为管理员，原有项目归最早的管理员；历史任务不补扣。
- 商业扣费关闭时，管理员保留原生成入口；普通成员没有绕过报价的生成入口。
- 每元默认兑换 100 平台积分。产生流水后不可修改，避免历史余额含义变化。
- 国内成本：260 元 / 6200 官方积分；国际成本：30 元 / 1500 官方积分；生图：0.10 元 / 张。
- 三个渠道独立配置成本加价比例，默认 0%，不是推荐售价。兑换、充值与计价都采用整数账本；报价向上取整到平台积分。

公式：视频平台积分 = ceil(官方积分 × 渠道采购人民币单价 × (1 + 成本加价比例) × 每元平台积分)。生图将渠道成本替换成每张成本。成本加价 50% 对应销售毛利率约 33.33%。

## 管理员开通顺序

1. 在 HTTPS 域名后部署 API；保留现有 master key，配置定期 SQLite 在线备份与媒体备份。不要将数据库、密钥、SMTP 密码提交 Git。
2. 登录管理后台，设置 SMTP 主机、465/587 端口、账号、密码、发件人，使用“发送测试邮件”验证真实投递。密码加密存储，接口不返回明文。配置成功后才可开启邮箱注册。
3. 设置微信号、二维码和充值说明。用户通过微信付款，管理员按收款金额入账，可附赠积分。每次入账必填备注并使用幂等请求标识；纠错追加调整流水，不修改历史账。
4. 配置国内、国际与生图的成本和加价。核对账号池及生图连接仍有效。用户只看模型名称和“快速/慢速”标签，不能访问账号池、接口密钥与代理。
5. 在公开模型目录设置模型名称、启用状态与预测消耗。优先按时长、分辨率和参考模式录入精确费率；每秒积分是显式备用规则。没有可用预测规则的视频模型不能报价。
6. 通过测试用户充值、小额生成、失败退款、下载恢复验收后，开启商业扣费。

## 报价和账本规则

- 当前生产渠道没有经过验证的官方预报价接口。界面明确显示“配置计价”，不会将推算值称为官方消耗，也不读取账号余额差值推算单任务费用。
- 报价有效期 5 分钟；冻结模型、成本、加价、素材指纹和公共风格。素材变更要求重新报价；有效报价期间的调价不追溯影响旧报价。
- 确认报价时同一 SQLite 事务创建任务和冻结积分。重复确认返回原任务；余额不足不创建收费任务。
- 本地成功保存可交付结果后扣费。确认失败、授权失效、取消未开始任务全额解冻。上游状态未知、查询失败或下载待恢复时保持冻结，避免已生成任务被重复提交。
- 已提供可信任务级实际消耗的适配器可通过 officialUsage 契约结算：必须带 official_actual 来源、与任务一致的 taskId 及 credits。现有适配器尚未验证提供该字段；目前按报价结算。未来接入实际消耗时可退差额，超过报价不追加扣费。
- 失败重试生成需要新报价、新冻结；下载重试不重复收费。图片资源不可用的重试继承 JPEG 兼容恢复。
- 长期无法交付由管理员核对官网任务后“确认未交付并退款”；该操作终止原任务，避免旧回调再次结算。已交付任务不能使用该入口。

## 数据与权限

新增表：commercial_settings、email_challenges、wallets、wallet_ledger、manual_topups、public_model_offers、generation_quotes、job_billing。项目增加 owner_user_id、asset_common_prompt；用户增加邮箱、角色、验证状态和启停状态。

普通用户只能访问自己创建的项目、媒体、任务、导出与事件。导入备份不接受上传文件指定的所有者。账号停用立即吊销会话；重置密码也会吊销旧会话。管理员保留跨项目管理权限。

公共风格与公共参考图并存；新的生图任务保存最终提示词快照，不回写资产原始描述，也不修改历史任务。场景无人规则继续生效。

## 升级与回滚

- 停止 API/worker 前检查在途任务；使用 SQLite backup API 备份数据库，保留 master key 和媒体。发布前先在副本迁移两次，核对 integrity_check、用户/项目/资产/任务数量和所有权。
- 部署 tracked 源码与构建后的 webapp/dist，运行 npm install --omit=dev，重启 API/worker；不要删除既有媒体、CLI 登录态、代理配置与旧前端哈希文件。
- 迁移是幂等、增量式，不删除旧业务列；发布验收前保持注册和商业扣费关闭。
- 若未产生新业务，可停服务后恢复代码及升级前数据库。若已产生充值/生成流水，禁止直接恢复旧数据库丢账，先备份当前库并做前向修复或人工对账。

## 验证范围

本地：151 项 Node 测试、10 项前端测试、TypeScript/Vite 构建通过。隔离浏览器验收走通注册验证码、登录、管理员充值、成员私有项目、公共风格、报价冻结、生图模拟交付与扣费账本（1000 → 985，冻结归零）。隔离环境的邮件及生成提供者使用测试替身，不冒充真实付费生成。

真实 SMTP 投递、用户最终售价以及官方任务级消耗仍需实际配置与上游能力验证；这些不通过测试替身宣称完成。
